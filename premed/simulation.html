학생 흐름 시뮬레이션 — 2026-10-13 밤

공개 페이지의 두 파일로 준비부터 연습 투고까지 실제로 돌린 기록입니다. 실습 문장 모음 · 자료 받기

공개 페이지에서 받은 prompt.md와 pipeline.zip만 빈 "다운로드" 폴더에 두고, Claude Code를 학생의 데스크톱 앱처럼 처음부터 끝까지 진행했습니다. 개인 설정과 MCP는 끈 깨끗한 세션이었고, 학생 역할은 강의 슬라이드의 문장을 붙이고 검토 화면에 직접 판단을 써서 저장하는 방식으로 했습니다. H4 비평은 폴더가 연결되지 않은 별도 새 대화에서 실제로 받았습니다.

결과

H1–H5, 통계 분석(StatSam), 제출 파일 묶음, 연습 투고까지 모두 실제로 끝났습니다.

  • 준비: READY, doctor 통과
  • 분석: 평균 차이 6.50점, 95% CI −1.74~14.74, p=.116, 결과 검증 통과
  • 단계: H1–H5 모두 학생 판단으로 통과, WORKSHOP_REVIEWED
  • 묶음: CLASSROOM_PACKAGE_VERIFIED, DOCX 본문과 승인 원고 일치
  • 연습 투고: TRAINING_SUBMITTED, 업로드 해시 일치, 실제 저널 전송 없음

학생이 보낸 메시지는 22개였고, AI가 처리한 시간은 모두 합쳐 약 14분이었습니다. 검토 화면 5번, 비평 화면 1번, 연습 투고 화면 1번을 학생이 직접 채웠습니다. 매 단계 끝에 AI가 "다음에 붙여 넣을 문장"을 알려 주어 흐름이 끊기지 않았습니다.

학생이 멈칫할 지점과 고친 것

AI가 학생 자신의 말을 기다리는 지점이 여섯 군데 있었고, 처음 슬라이드에는 무엇을 보내야 하는지가 없었습니다. 모두 슬라이드에 넣었습니다.

  1. 준비가 끝나면 AI가 주제, 자료 종류, 모델 이름을 묻습니다. 자료 종류는 나중에 바꿀 수 없습니다. → 15장 문장이 세 가지에 한 번에 답하고, 끝의 "내 질문:" 뒤에 학생이 한 문장을 덧붙입니다. 재시험에서 되묻지 않고 H1 프로젝트가 바로 만들어졌습니다.
  2. 자료 사전에는 guided가 가상의 학습 조건이라고만 적혀 있어, AI가 단계마다 "힌트형 AI 집단으로 볼지"를 다시 물었습니다. → 14·15장에 "guided를 힌트형 AI 연습 집단으로 가정"을 명시했습니다.
  3. H2는 학생의 주장 한 문장이 있어야 검색을 시작합니다. → 16장 문장에 예시 주장을 넣었습니다. 재시험에서 바로 출처 검색으로 넘어갔습니다.
  4. 분석은 가정 하나를 자기 말로 설명하고 "이 질문과 분석계획을 읽고 승인합니다"를 직접 보내야 실행됩니다. → 17·18장에 넣었습니다.
  5. H3 전에 AI가 결과 해석을 학생의 말로 받습니다. → 19장에 "결과를 내 말로 2–3문장" 안내를 넣었습니다.
  6. 묶음 전에 저자 표시, 단독 저자·IRB·이해충돌, 공개문 확인, 다른 AI 사용 여부를 묻고, 두 파일을 읽은 뒤의 지시 문장을 기록합니다. → 23장에 카드로 넣었습니다.

슬라이드의 문장은 프로젝터로만 보여서 학생이 긴 문장을 직접 타이핑해야 했습니다. 같은 문장을 순서대로 모으고 복사 버튼을 단 "실습 문장 모음"(/premed/steps.html)을 만들어 자료 페이지와 12장에서 연결했습니다. 막혔을 때 보내는 문장(현재 단계 묻기, 검토 화면 다시 열기, 연습 투고 서버 다시 켜기, 중간 저장)도 같은 페이지에 있습니다.

순서도 하나 고쳤습니다. 문장 다듬기(22장)를 H5 판단 저장 뒤에 하면 승인한 파일이 바뀌어 단계를 다시 열어야 합니다. 그래서 22장을 "H5 안에서, 판단 저장 전에"로 바꿨습니다.

2차 리허설 — 2026-10-14 아침, 수정한 pipeline.zip

첫 리허설에서 나온 문제를 파이프라인에도 반영한 뒤(138,557바이트 판), 공개할 두 파일로 새 폴더에서 처음부터 다시 돌렸습니다. 학생 문장은 수정한 슬라이드와 실습 문장 모음을 그대로 썼습니다.

  • 연습 투고 서버: AI가 finish.py portal --detach로 띄웠고, 대화 턴이 끝난 뒤에도 주소가 응답했습니다. 학생이 제출하자 접수증(TRAINING_SUBMITTED)이 생겼고, 업로드 해시가 묶음과 같았으며, 서버는 몇 초 뒤 스스로 꺼졌습니다. 첫 리허설에서 서버가 꺼지던 문제가 해결되었습니다.
  • 답 길이: AI 답이 "한 일 → 경고 → 학생이 할 일 → 다음 문장" 순서로 짧아졌습니다. 첫 리허설의 30–40줄이 대체로 7–23줄로 줄었습니다.
  • 시간: 준비 약 2분, H2 출처 검색 약 2분, 통계 도구 설치 약 3분 30초(패키지를 새로 받음, 쉬는 시간 직전에 요청하는 이유), 분석 계획과 실행 각 40초 안팎, H3 전체 원고 약 1분, 비평 대화 약 50초, H5 약 2분, 묶음 세 번 주고받기 약 1분 40초, 연습 투고 화면과 접수증 확인 각 20–25초였습니다.

새로 찾은 것과 고친 것:

  1. H4 판정을 번호 없이 보내면("가장 중요한 지적 하나는 채택") AI가 몇 번인지 되묻고 검토 화면을 만들지 않습니다. 그 상태에서 이전 단계의 검토 화면을 다시 저장해도 반영이 거절됩니다. 파이프라인은 상태를 바꾸지 않고 이유와 다음 문장을 안내했습니다. → 20장과 실습 문장 모음에 "번호로 답하기(예: 2번 채택, 1번 보류)"를 넣었습니다.
  2. 묶음 질문에 "이 대화 밖에서는 AI를 쓰지 않았다"고 답하자, AI가 H4 비평을 받은 새 대화도 바깥 AI 사용이라고 바로잡았습니다. → 23장과 실습 문장 모음의 질문을 "비평 대화 말고 따로 쓴 AI가 있는지"로 바꿨습니다.
  3. 순서를 건너뛴 요청(H4가 끝나기 전의 H5, 묶음, 연습 투고)은 모두 거절되었고, AI가 남은 순서와 다음 문장을 알려 주었습니다. 학생이 순서를 놓쳐도 다시 돌아올 수 있습니다.

확인하지 못한 것과 남은 위험

  • 연습 투고 서버: 2차 리허설에서 분리 실행으로 해결했지만, Codex 앱에서는 확인하지 못했습니다. 24장과 실습 문장 모음의 "서버를 다시 켜 달라고 보내기"는 그대로 둡니다.
  • ChatGPT(Codex) 경로, Python이 없는 새 노트북, 교실 Wi-Fi에서 StatSam 패키지 동시 설치는 시험하지 않았습니다. 이 PC는 Python과 uv가 이미 있어 설치가 빨랐습니다.
  • 학생의 실제 읽기·쓰기 시간은 측정하지 않았습니다. AI 처리 시간 14분에 검토 화면 다섯 번의 작성 시간을 더하면 실습 105분 안에 들어갈 것으로 보지만, 실학생 기록은 아닙니다.
  • 시뮬레이션의 학생 판단은 진행자가 학생 입장에서 작성한 시험 기록입니다. 실제 학생의 판단이 아닙니다.
