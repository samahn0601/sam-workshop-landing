🔒 안전 게이트 5 · 생략 불가

파이프라인 구조는 트랙마다, 참가자마다 다르게 바꾸셔도 됩니다. 다만 아래 다섯은 어떤 구조에서도 남습니다 — 되돌릴 수 없는 종류이기 때문입니다.

게이트왜
🔒 학습 끄기 실제 원고·연구 자료가 모델 학습에 들어가면 되돌릴 수 없습니다.
ChatGPT 개인 계정 — 앱 설정 → 계정(↗) → 웹 설정 → 데이터 제어 → 「모델 개선을 위한 데이터 학습 허용」 꺼짐.
Claude 개인 계정 — claude.ai 설정 → 개인정보(Privacy) → 모델 개선 허용을 끕니다. 주소는 claude.ai/settings/data-privacy-controls 이고, 메뉴 이름은 화면 기준으로 확인하세요.
업무용(Team·Business·Enterprise) 계정은 이 개인 설정 항목이 없을 수 있고 학습 정책은 기관 계약을 따릅니다. 소속 기관 관리자 정책을 확인하세요.
🔒 환자 데이터 반입 금지IRB 승인을 받은 연구 데이터여도 이 실습 폴더에 넣지 않습니다. 오늘은 비식별·합성 자료로 합니다.
🔒 인용 실재 확인날조 인용은 데스크 리젝트를 넘어 연구 진실성 문제가 됩니다.
🔒 제출은 사람이포털 로그인·제출 버튼은 저자 본인의 행위입니다. AI가 누르지 않습니다.
🔒 의학적 판단 확인약물 용량·IRB·가이드라인 서술은 저자가 책임집니다.
⚠️ 오늘 만드는 산출물은 투고를 향한 원고(submission-directed)이지 투고 가능한 원고(submission-ready)가 아닙니다. 실제 투고 전에 참고문헌·데이터·AI 공개문·공저자 승인을 본인이 최종 확인하셔야 합니다.

🪄 AI가 "안 됩니다"라고 할 때 — 이걸 붙여넣으세요

가장 자주 겪는 실패는 기능이 없어서가 아니라 AI가 지레 "불가능하다"고 답해서입니다. 아래는 그 판단을 강제로 점검시키는 규칙입니다.

## 실현가능성 판단 규칙 불가 판정 전에 다음을 구분하라. 1. 기술적으로 불가능 2. 공식 지원은 아니지만 가능 — 쓸 경우 비공식 경로임을 반드시 밝힌다 3. 현재 방법만 실패 4. 정보나 권한이 부족함 5. 정책상 하지 않음 — 1번과 섞지 말 것. 우회로를 찾지 말 것. "불가능"이라고 답하려면 공식 문서 · 실제 오류 메시지 · 환경 제약 중 최소 하나의 명확한 근거를 제시해야 한다. 그전에는: - 현재 환경과 설치된 도구를 직접 확인한다 - 공식 경로를 우선 탐색한다 - 첫 실패 후 최소 2개의 대안을 시도한다 - 오류 메시지를 근거로 계획을 수정한다 - 대안이 소진되거나 도구 호출 20회를 넘기면 멈추고 현황을 보고한다 설명만 하지 말고 실제로 수행하라. 성공 보고도 같은 기준이다 — 실행 출력이나 테스트 결과 없이 "됐습니다" 금지. 막히면 "안 된다"가 아니라 어디까지 성공했고 무엇이 막혔는지 보고하라. 예외 — 되돌릴 수 없는 작업은 이 규칙 밖이다. 삭제, 원고 덮어쓰기, 결제, 외부 전송, 저널 제출, 인증정보 입력, force push, DB 마이그레이션은 시도 전에 먼저 확인받는다.
📌 매번 붙여넣기 번거로우시면 — 파일에 넣어두시면 됩니다.
작업 폴더에 파일을 만들고 위 내용을 넣으면, 그 폴더에서는 항상 적용됩니다. 만드는 것도 시킬 수 있습니다 — "이 폴더에 파일 만들고 방금 규칙 넣어줘". Codex는 AGENTS.md, Claude Code는 CLAUDE.md가 같은 역할을 합니다.
⭐ 왜 이게 오늘의 핵심에 닿는가 — 이 규칙의 마지막 두 줄이 진짜입니다.
"실행 출력 없이 '됐습니다' 금지" · "어디까지 성공했고 무엇이 막혔는지 보고하라"
AI가 안 된다고 할 때도, 됐다고 할 때도 근거를 요구하는 것 — 그게 오늘 배우실 판단의 전부입니다. 되돌릴 수 없는 일(삭제·제출·결제)에는 이 규칙을 적용하지 않는다는 예외도 같은 이유입니다.

🧪 AI가 "검사했습니다"라고 할 때 — 이것도 붙여넣으세요

두 번째로 자주 겪는 실패는 검사를 하지 못했는데 "통과"라고 답하는 것입니다. 검사 결과에 상태와 숫자를 붙이게 하는 규칙입니다.

## 검증 보고 규칙 검사 결과는 네 가지 상태로만 보고한다. - PASS: 검사했고 문제 없음 - FAIL: 검사했고 문제 발견 - INCOMPLETE: 검사하지 못함 (입력 없음, 도구 없음, 네트워크 없음) - N/A: 해당 없음 검사하지 못한 것을 PASS라고 쓰지 않는다. "확인했습니다"만으로는 보고가 아니다. 모든 검사 보고에는 숫자를 붙인다. - 대상: 검사해야 할 항목 수 (예: 참고문헌 32건) - 검사: 실제로 대조한 수 (예: 29건) - 미검사: 못 한 수와 이유 (예: 3건, DOI 없음) - 발견: 문제 수와 위치 인용은 존재 여부만이 아니라 저자·연도·저널이 원고와 같은지, 철회(retraction)되지 않았는지까지 본다. 재계산할 수 있는 숫자는 재계산한다 (백분율과 분모, 표 합계, p값과 검정통계량). 말로만 보고하지 말고 도구 출력(실행한 명령, 결과 파일)을 함께 보여라.
📌 앞의 규칙과 같은 파일(AGENTS.md / CLAUDE.md)에 이어서 넣으시면 됩니다.
⭐ 목표는 검사 개수가 아니라 "검사 안 했는데 통과"가 0건인 것입니다. ⑤ 인용 검증과 ⑦ 투고 전 점검에서 도구가 통과라고 하면 "몇 건 중 몇 건을 대조했나"를 되물으세요. 「공개 도구」 절의 도구도 같은 원칙(검사 못 함 = 통과 아님)을 코드로 강제합니다.
