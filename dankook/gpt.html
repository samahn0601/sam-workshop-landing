1. 아래를 받아 그대로 두세요. 압축은 직접 풀지 마세요 — Codex가 풀고, 제대로 풀렸는지 확인까지 합니다.

2. ChatGPT 앱 → 왼쪽 위 Codex → 프로젝트 선택 → 새 프로젝트로 다운로드 폴더를 엽니다.

3. 아래를 붙여넣고 실행하세요.

이 폴더에서 paper-workshop.zip 을 찾아 압축을 풀어줘. 압축을 풀었을 때 paper-workshop 안에 같은 이름 폴더가 한 겹 더 생기면, 안쪽 내용을 위로 올려서 정리해줘. 다 되면 확인해서 알려줘 — · paper-workshop 안에 AGENTS.md 와 .agents 폴더가 있는지 · .agents/skills 안에 폴더가 몇 개인지 (숫자로) 원래 zip 파일은 그대로 두고, 이 폴더의 다른 파일은 건드리지 마.

🪟 여기서 승인 창이 처음 뜹니다. 압축을 풀려면 명령을 하나 실행해야 하기 때문입니다 — 허용을 누르면 진행됩니다. 무엇을 하려는지 창에 그대로 적혀 있으니, 읽고 누르는 습관을 가장 안전한 작업에서 들이는 셈입니다.

4. 20개 또는 21개라고 답하면 성공입니다.

💡 21개도 정상입니다 — _shared는 도구가 아니라 여러 도구가 같이 쓰는 공용 자료 폴더라서요. 숫자가 0이나 1이면 폴더가 한 겹 더 있는 경우이니, "안쪽 폴더를 위로 올려줘"라고 다시 말씀하시면 됩니다.

5. 프로젝트 선택 → 새 프로젝트로 이번엔 paper-workshop 폴더 자체를 열어주세요.

이 한 번은 손으로 하셔야 합니다. 이후 모든 요청이 "이 폴더의 …"를 전제로 하기 때문에, 작업 자료만 든 폴더를 열고 있어야 결과가 정확합니다.

🔒 다운로드 폴더에 민감한 파일이 있다면 — Codex는 내가 연 폴더를 봅니다. 환자 자료나 심사 중 원고가 다운로드 폴더에 있다면, 바탕화면에 새 폴더를 하나 만들어 zip만 옮겨 넣고 그 폴더를 여세요. 다음은 위와 똑같습니다. "폴더를 고르는 것이 곧 안전 경계"라는 게 이런 뜻입니다.

둘 다 선택입니다. 다만 받아쓰기는 한번 써보시길 — 연구 아이디어를 말로 풀어놓는 편이 타이핑보다 잘 나오는 분이 많습니다.

8⑥ 심사자 비평 · 블라인드 3인 리뷰

이 워크숍의 핵심 도구입니다. 리뷰어 세 명이 각각 새 대화에서 원고만 보고 읽습니다.

왜 새 대화에서 따로 읽는가

같은 대화 안에서 페르소나만 바꾸면, 초안을 쓸 때 세운 전제와 표현이 그대로 남아 있습니다. 그러면 리뷰어 셋이 같은 맹점을 그대로 공유합니다. 그리고 모델은 자기가 방금 쓴 글에 관대해집니다 — 원고를 처음 보는 심사자라면 곧바로 잡아낼 약점을 그냥 지나칩니다.

그래서 리뷰어에게 넘기는 것은 원고 파일과 필요한 참고 파일뿐입니다. 초안을 쓴 대화 내용, 다른 리뷰어의 결과는 보여주지 않습니다.

리뷰어보는 것
R1 방법론 리뷰어연구 설계, 표본, 교란, 일반화 가능성
R2 통계·논리 리뷰어통계 보고, 논증 흐름, 인과관계 비약
R3 가혹한 데스크 에디터데스크 리젝 사유, novelty, 임상 함의, 저널 fit — 기본 판단은 리젝이고 저자가 그걸 뒤집을 근거를 원고에서 찾습니다
⭐ 이 단계만 무겁게 — 셋 다 현재 플랜에서 가장 상위 모델과 가장 높은 추론 강도로 돌립니다(§3 표의 "⑥ 심사자 비평 때" 값). 약점 탐지는 추론 깊이가 결과를 그대로 바꿉니다. 끝나면 평소 설정으로 되돌리세요.

구독 티어별 실행 경로

Pro 구독자 — Codex가 인앱 브라우저에서 chatgpt.com 새 대화 세 개를 열어 Pro 프리셋으로 각각 돌리고, 결과를 파일로 저장합니다. 로그인은 사람이 합니다(비밀번호 대리 입력 없음). 화면에 있는 것만 저장하고, 요약하거나 보충하지 않습니다.

Plus 구독자 — Codex 새 스레드 세 개에서 원고만 첨부해 각각 실행합니다. 모델과 추론 강도는 §3 표의 "⑥ 심사자 비평 때" 칸을 씁니다.

둘 다 어려우면 — 같은 대화에서 페르소나 셋을 순차로 돌립니다. 이때는 독립성이 떨어진다는 점을 저자에게 한 줄로 알려야 합니다 — 초안의 전제를 세 리뷰어가 공유하게 되기 때문입니다.

⑥ 심사자 비평을 블라인드 3인으로 돌려줘. 나는 [Plus/Pro] 구독자야
엇갈리는 지적이 가장 값집니다. 세 리뷰어가 만장일치로 든 항목은 대개 저자도 이미 아는 약점이고, 한 명만 본 것과 서로 반대로 판정한 것이 블라인드 구성으로만 얻는 정보입니다.

다른 회사 모델을 네 번째 심사자로 붙이는 방법은 병용 트랙 안내에 있습니다.

10더 넓히기 · 선택 · 여유가 되는 만큼 · 안 하셔도 실습에 지장 없습니다

① Git — 원고를 되돌릴 수 있게 선택

원고를 고치다 보면 "아까 그 문장이 나았는데" 하는 순간이 옵니다. Git이 있으면 어느 시점으로든 되돌릴 수 있습니다.

ChatGPT는 Claude와 달리 Git을 처음부터 요구하지 않습니다. 없어도 오늘 실습은 전부 됩니다. 다만 원고 이력 관리에는 있는 편이 낫습니다.

아래를 그대로 붙여넣으면 설치까지 알아서 합니다 — 설치 파일 정리까지 포함입니다.

Git이 설치돼 있는지 확인하고, 없으면 설치해 줘. 순서는 이렇게: 1. 먼저 `git --version` 으로 확인해. 이미 있으면 버전만 알려주고 끝내. 2. 없으면 — Windows는 `winget install --id Git.Git -e --source winget` 을 먼저 시도해. 설치 파일이 남지 않아 가장 깔끔해. (Mac이면 `brew install git`) 3. winget이 없거나 실패하면: git-scm.com에서 최신 64비트 설치 파일을 임시 폴더에 받아 조용히 설치(/VERYSILENT /NORESTART)한 뒤, **받은 설치 파일을 반드시 삭제**해. 임시 폴더도 남기지 말고 정리해. 4. 새 셸에서 `git --version` 으로 재확인하고 결과를 한 줄로 알려줘. PATH에 안 잡히면 앱을 껐다 켜야 한다는 것도 알려줘. 각 단계에서 무엇을 할지 먼저 말하고 진행해. 실패하면 멈추고 무엇이 왜 실패했는지 알려줘. 관리자 권한이 필요하면 먼저 물어봐.

설치 후 원고 폴더에서 "지금 상태를 저장해 둬", 나중에 "아까 저장한 걸로 되돌려 줘" 라고 하시면 됩니다. Git 명령을 외우실 필요 없습니다.

14AI가 "안 됩니다"라고 할 때

🪄 AI가 "안 됩니다"라고 할 때 — 이걸 붙여넣으세요

가장 자주 겪는 실패는 기능이 없어서가 아니라 AI가 지레 "불가능하다"고 답해서입니다. 아래는 그 판단을 강제로 점검시키는 규칙입니다.

## 실현가능성 판단 규칙 불가 판정 전에 다음을 구분하라. 1. 기술적으로 불가능 2. 공식 지원은 아니지만 가능 — 쓸 경우 비공식 경로임을 반드시 밝힌다 3. 현재 방법만 실패 4. 정보나 권한이 부족함 5. 정책상 하지 않음 — 1번과 섞지 말 것. 우회로를 찾지 말 것. "불가능"이라고 답하려면 공식 문서 · 실제 오류 메시지 · 환경 제약 중 최소 하나의 명확한 근거를 제시해야 한다. 그전에는: - 현재 환경과 설치된 도구를 직접 확인한다 - 공식 경로를 우선 탐색한다 - 첫 실패 후 최소 2개의 대안을 시도한다 - 오류 메시지를 근거로 계획을 수정한다 - 대안이 소진되거나 도구 호출 20회를 넘기면 멈추고 현황을 보고한다 설명만 하지 말고 실제로 수행하라. 성공 보고도 같은 기준이다 — 실행 출력이나 테스트 결과 없이 "됐습니다" 금지. 막히면 "안 된다"가 아니라 어디까지 성공했고 무엇이 막혔는지 보고하라. 예외 — 되돌릴 수 없는 작업은 이 규칙 밖이다. 삭제, 원고 덮어쓰기, 결제, 외부 전송, 저널 제출, 인증정보 입력, force push, DB 마이그레이션은 시도 전에 먼저 확인받는다.
📌 매번 붙여넣기 번거로우시면 — 파일에 넣어두시면 됩니다.
작업 폴더에 파일을 만들고 위 내용을 넣으면, 그 폴더에서는 항상 적용됩니다. 만드는 것도 시킬 수 있습니다 — "이 폴더에 파일 만들고 방금 규칙 넣어줘". Codex는 AGENTS.md, Claude Code는 CLAUDE.md가 같은 역할을 합니다.
⭐ 왜 이게 오늘의 핵심에 닿는가 — 이 규칙의 마지막 두 줄이 진짜입니다.
"실행 출력 없이 '됐습니다' 금지" · "어디까지 성공했고 무엇이 막혔는지 보고하라"
AI가 안 된다고 할 때도, 됐다고 할 때도 근거를 요구하는 것 — 그게 오늘 배우실 판단의 전부입니다. 되돌릴 수 없는 일(삭제·제출·결제)에는 이 규칙을 적용하지 않는다는 예외도 같은 이유입니다.

15이게 다 뭐예요? · 한 줄 정리

Codex — ChatGPT 데스크탑 앱 안의 모드. 채팅과 달리 내 컴퓨터의 진짜 파일을 읽고 씁니다. 웹·모바일에는 없습니다.

skill — SKILL.md 한 장. "이런 요청이 오면 이렇게 하라"고 적어둔 설명서입니다.

인앱 브라우저 — 앱 안에 들어 있는 브라우저. Codex가 화면을 직접 보고 조작할 수 있습니다.

딥리서치 — ChatGPT가 여러 자료를 찾아 읽고 정리해주는 기능. 다만 인용은 반드시 검증해야 합니다.

블라인드 리뷰 — 리뷰어 세 명을 각각 새 대화에서 원고만 보고 읽게 하는 방식. 같은 맹점을 공유하지 않게 합니다.

오늘 배우시는 건 도구 사용법이 아니라 판단입니다.
무엇을 AI에게 맡기고, 무엇을 반드시 사람이 확인해야 하는지 — 그 선을 긋는 감각이 남으면 오늘은 성공입니다. 도구는 6개월이면 바뀌지만 그 선은 바뀌지 않습니다.
